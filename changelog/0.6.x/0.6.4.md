# 0.6.4 — 2026-09-21

## Changed

- **Argument rejections** carry `data.reason: "invalid_arguments"` and a schema-derived `Recovery:` hint naming what to send — a missing `stationId` reads `Provide stationId.`, an unknown key `bogusKey` reads `Unknown key bogusKey. This tool accepts: stationId.` (mcp-ts-core 0.13.3).
- **Argument keys** differing from a declared key only in case or `-`/`_` are rewritten and accepted, and a JSON-stringified array is repaired after a failed parse; client-added root keys (`_meta`, `tool_call_description`, `toolCallId`) are dropped; any other undeclared key is still rejected (mcp-ts-core 0.13.4).
- **Tool error text** closes with `(reason <reason>)`, adding ` · retryable` / ` · not retryable` when the contract entry declares `retryable`; `structuredContent` is unchanged (mcp-ts-core 0.13.5).
- **Minor/internal:** service-raised `malformed_export` reasons marked `thrownBy: 'service'` (lint-only metadata; the advertised contract is unchanged), CodeQL workflow added, `framework-skills/` and `scripts/lint-mcp.ts` resynced to 0.13.6 (`devcheck.config.json` gains the `lint` key), `CLAUDE.md`/`AGENTS.md` and both issue forms aligned to the template, `.env.example` documents `MCP_LOG_RATE_LIMIT_THRESHOLD`/`MCP_LOG_RATE_LIMIT_WINDOW_MS` and `MCP_HTTP_MAX_BODY_BYTES` and rewords the GC comment (comment-only, no default changes).

## Fixed

- **`malformed_export` failures** from `noaa_climate_search_storm_events` and `noaa_climate_get_billion_dollar_disasters` now carry each tool's declared recovery hint in `error.data.recovery` (mirrored into `content[]`); the services previously threw the reason without the hint.
